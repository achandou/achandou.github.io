Hexo 写作指南：Markdown、图片与排版

发表于 2023-03-10 分类于 工具
整理 Hexo 文章里最常用的 Markdown 写法、图片插入方式、摘要分隔和排版注意事项。

这篇原本只是记两条插图语法，后来发现每次写文章都会回来查，就整理成一份自己的排版清单。重点放在 Hexo 特有的图片写法，以及哪些看起来能用的写法会悄悄把段落变成代码块。

一、Front-matter

每篇文章开头的两行 --- 之间是元数据：

  • encrypt: true：正文用 AES-GCM 加密，阅读时需要输入密码。
  • description：首页摘要；不写的话，主题可能截取正文开头。
  • tags 建议从固定词表里选，避免标签越写越碎。

三、插入图片

这个博客开启了 post_asset_folder，文章资源放在与 Markdown 同名的文件夹里：

方法一：Hexo 标签

优点是路径由 Hexo 处理，文章搬到子目录也不会失效；缺点是不能直接控制宽高和对齐。

方法二：Markdown 相对路径

需要主题支持资源路径解析。部分主题还支持在地址后加 #pic_left、#pic_center、#pic_right 控制对齐，但这是主题扩展语法，换主题不一定有效。

如果图片放在网上（图床、GitHub raw），直接把图片地址填进 src 即可。注意 GitHub 的 raw 地址在国内访问可能不稳定，重要图片建议随文章一起放在资源目录。

四、摘要分隔

<!-- more --> 之前的内容会作为列表页摘要。但这个博客开启了 excerpt_description，优先用 front-matter 的 description，所以最省事的做法是：description 写一句话，正文里不再手动截断。

五、容易踩的坑

  1. 四个空格缩进会变成代码块：从别的编辑器粘贴内容时，最容易把普通段落粘成代码块。检查行首是否有 4 个空格或 Tab。
  2. HTML 和 Markdown 混排要留空行：块级 HTML 前后空一行，否则 Markdown 解析器可能把后面的内容吞进 HTML 块。
  3. 中文文件名会进入 URL：文章文件尽量用英文或拼音命名，标题再用中文；否则分享链接时会出现一长串 %E4%B8%AD%E6%96%87。
  4. 图片路径大小写：Windows 不区分大小写，GitHub Pages 区分，Image.png 和 image.png 是两张图。
  5. 加密文章不要放敏感图片到公开资源目录：加密只保护正文文本，图片如果放在公开路径，仍然可能被直接访问。

六、这个博客的写作流程

新建后直接用编辑器打开 source/_posts/文章标题.md，图片拖进同名资源目录，写完发布即可。
